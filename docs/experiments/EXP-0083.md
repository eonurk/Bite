# EXP-0083: linear-time BWT suffix sorting

## Hypothesis

Rotation sorting is about 90% of mode-25 encode time. In CPU time on the
laptop, it takes 1.93 of 2.10 seconds on E.coli and 1.48 of 1.54 seconds on
bible.txt. The prefix-doubling sorter needs about log2(longest repeat) radix
passes with random access. Sorting the suffixes of the doubled block `TT` with
SA-IS is linear time and should cut `cbwt` encode time at least threefold
without changing a single output byte.

For an aperiodic block, every rotation is distinct and is decided within `n`
characters. So the order of suffixes of `TT` that start before `n` equals the
rotation order, and the last column and primary index are identical to the
current encoder's. A block that is an exact repetition of a shorter string has
equal rotations, whose relative order is implementation-defined. Those blocks
keep the prefix-doubling sorter, so every stream stays byte-identical.

## Protocol

- Encoder-only change; the mode-25 format and decoder are untouched.
- Exact check: `cbwt` and `cmax` streams must be byte-identical to `main` on
  every development and research file, and on forced periodic, random and
  all-equal inputs.
- Measurement: CPU time of the rotation sort and of whole-file `cbwt` encoding
  before and after, on the same machine (m1-2), process harness, 3 repeats.
- Decision: keep if output is identical everywhere and `cbwt` research encode
  time falls by at least 2x.

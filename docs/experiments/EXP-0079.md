# EXP-0079: bitwise context-mixing literal coder (block mode 28, preset `ccm`)

## Hypothesis (written before measurement)

Brotli 11 beats `cmax` on all 12 smaller Calgary files because Bite's best
generic literal model (mode 24, EXP-0074) only blends order-1/exact order-2
counts with cautiously trusted hashed order-3 and word-suffix contexts by
fixed-rule frequency averaging. A logistic (stretch/squash) mixer with learned
weights selected by small contexts, fed by more contexts (orders 1-6, sparse,
word, column) and a match model, then refined by adaptive probability maps
(SSE/APM), should code these files well below `cmax` and Brotli 11. Because
`ccm` exact-selects mode 28 next to every `cmax` candidate, it cannot enlarge
any block; the research aggregate should fall below `cmax`'s 3,247,227 bytes.

Mode 28 codes every byte of a block with the mixed model (no LZ parse). The
match model takes the place of match lengths/distances: it predicts the byte
following the most recent occurrence of the current six-byte context, and its
expected bit and length bucket are both mixer inputs and mixer weight-set
selectors, so repeated strings are modelled by the same mixer as literals.
All contexts are rebuilt from bytes already decoded in the block.

Assigned identifiers: block mode 28, `compress_linked_blocked` entropy_parse
38, CLI preset `ccm`.

## Design of mode 28

`src/bite_cm.h`; payload format in `docs/format.md`.

- Bits are coded MSB first by a carry-less 32-bit binary arithmetic coder
  with 16-bit probabilities. It flushes four bytes, and the decoder must
  consume exactly the stored payload.
- Contexts (14): order 0, 1, 2, 3, 4, 6; current-word hash with previous-word
  hash; column with the byte above; bytes 2 and 4 (`c4 & 0xffff0000` with
  byte 5); skip-one (byte 2 alone); word plus previous byte; bytes 5-8;
  bytes 3-4; indirect (the two bytes that last followed the current order-2
  context, plus order 1). All are rebuilt from decoded bytes; nothing
  dispatches on file names, extensions or position.
- Each context hashes, at every nibble boundary, to a 16-byte bucket (an 8-bit
  check plus 15 bit-history states) and probes 2 ways. On a miss the bucket
  with the lower first-slot count is replaced. States are bounded
  (zeros, ones) pairs, at most 30 each; on each update the opposite count is
  discounted to (n+2)/2 when it exceeds 2. One adaptive map per context turns
  each state into a probability (rate 1/(n+1.5), limit 1023).
- Match model: a hash of the last 6 bytes finds the most recent occurrence,
  and the match length is verified backwards. While the predicted byte agrees
  with the bits coded so far, an adaptive map indexed by (length bucket,
  expected bit) supplies a stretch input, plus a signed length input.
- Mixer inputs: stretch(p) and (p-2048)/4 for each context, the two match
  inputs, and a bias, 31 inputs in all. Four first-layer logistic mixers
  choose their weight sets by the partial byte, match state × bit position ×
  expected bit, the previous byte, and the byte before it. A second-layer
  mixer (weights chosen by the partial byte) combines them. The learning rate
  is 8/8 plus a 16/8 boost that halves after 4,096 bytes.
- Final probability: (2·mixer + APM(partial byte) + APM(order 1) +
  APM(match state)) / 5. Each APM has 33 interpolated buckets at rate 1/128.
- Table size grows with the block: 16-byte buckets, 2^k bytes per context with
  k = ceil(log2(2·block)) clamped to 16..24. The order-0 and order-1 tables
  are capped at 2^20 bytes. For a whole 16 MiB block the model uses
  about 14 × 16 MiB + 4 MiB match table + 6.4 MiB of APMs, about 235 MiB.
  Peak RSS was not measured.

Mode 28 is symmetric: it decodes at roughly 0.3-0.4 MB/s here, while the
mode-24 decoder is an LZ parse plus literal decoding whose speed tracks the
compressed size. `ccm` encoding adds one mode-28 pass to `cmax`. On the
generated dev files the `ccm` run took 104 s against 88 s for `cmax` in this
environment (one repeat, same-machine ratio 1.18).

## Correctness

- `ccm` round-trips (in-process harness, exact comparison) on every available
  dev file. These are the 15 generated files; the Canterbury files were
  unavailable. It also round-trips on the 11 samples. `cmax` round-trips on
  the same files in the same runs.
- `scripts/test_cm.py` (`make test-cm`) passes plain and with `--sanitize`
  (ASan+UBSan, gcc). It checks 9 exact-selection round trips in which `ccm`
  output must equal `cmax` output unless it is strictly smaller with block
  mode 28; empty, 1-byte, random, periodic and 4-symbol inputs are among
  them. It also checks `dwork`/`dslow` decoding and 929 rejected malformed
  streams: every truncation, trailing bytes, stored size shortened or
  lengthened by one byte, and a payload shorter than the coder state. Finally
  it runs 100 random bit flips, which must exit cleanly.
- Byte identity against a `main` build (same compiler): `cmax`, `cfast` and
  `cbwt` on 13 files (all generated small files, records.bin,
  pseudo_text.bin, gpl3, services, stdlib.h, zstd.html, ls) and the EXP-0074
  mode-24 preset on 3 files all match exactly. Historical code paths were not
  modified; mode 28 is reached only through entropy_parse 38.
- Build: `cc` (gcc 13) gives the same warning set as `main` and no new
  warnings; `clang` builds `bin/bite` warning-free. `bin/bite-bench` does not
  build on Linux with `-std=c11` on `main` either (`CLOCK_MONOTONIC`). It was
  built here with `-D_POSIX_C_SOURCE=200809L` added on the command line; the
  Makefile is unchanged.
- The full `scripts/test_roundtrip.py`, which covers about 40 historical
  modes, was not run, as the coordinating session asked.

## Decision

**KEEP as a candidate, pending research confirmation.** Wherever it could be
measured, mode 28 is a large, consistent gain, and `ccm` cannot be larger
than `cmax` per block. On the generated dev files the gain is −20.3% with no
file larger. On the samples it is −22.2%, and `ccm` beats xz −9e on every
sample. Nothing here shows whether the research aggregate falls below
3,247,227 bytes or whether the 12 small Calgary files fall below Brotli 11,
so the size-max endpoint should not move to `ccm` until the research screen
above has run. The cost is decoding about 14× slower than mode 24 (same
machine), plus about 235 MiB of model memory for a full 16 MiB block.
